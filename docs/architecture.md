# 系统架构与扩展

## 当前依赖关系

```text
TushareSource / CSV / demo
           ↓ Bar + trading calendar
    Backtest 逐交易日推进
           ↓ 截至当日收盘的历史
    Strategy.on_close → Intent
           ↓ 次交易日触发
    FixedAccountPolicy → 风险预算倍率
    RiskManager → 审核、组合仓位、数量
           ↓
    模拟成交 → Position → 收盘跟踪止损
           ↓
    决策 / 订单 / 交易 / 净值 / 运行快照
```

- `domain.py`：稳定数据契约，Intent 保存策略归属、设置 ID、触发价、失效价、独立预估目标。
- `analysis.py`：因果波谷识别、复权转换、完整周线聚合。
- `strategies/`：插件及注册表，策略参数与组合限制分离。
- `risk.py`：共享组合风控和账户策略接口，阻止同一股票被多个策略重复占有。
- `engine.py`：事件推进、成交与组合账本。当前一个文件内分方法组织；复杂度增加后再提取 execution/portfolio/evaluation，避免两套账本。
- `data.py`：Tushare、缓存、校验、CSV，不参与交易判断。
- `cli.py`：运行编排、版本指纹、输出报告。

## 新策略接入

1. 新增 `strategies/<name>.py`，实现 `on_close(history, week_ends)` 和 `trailing_stop(history, position)`。
2. 注册 REGISTRY 类型；配置加入独立 id 与 params。多个实例可同时运行。
3. 只输出 Intent 和可审计事件；共享风控、资金和交易日历，禁止自建资金池。
4. 同日意图按配置中的策略顺序、股票代码排序；不使用后续表现选择优先级。
5. 初期一股票一归属，已有持仓拒绝其他策略入场。未来若支持子仓，必须明确风险聚合和退出归属。
6. 新退出模型应扩展稳定接口，由执行层解释，不能在插件里直接卖出。

尚未实现的功能：加减仓意图、行业相关性预算、指数环境门控、赢冲输缩、三元一体、波士顿循环、实盘 broker。当前是研究回测系统，不发送实盘订单。

## 数据与执行约定

- Tushare 按股票及年度获取 daily/adj_factor/stk_limit，使用 trade_cal 判断开市与完整周。缺少因子或涨跌停数据直接失败，不猜测板块限制。
- 波谷、颈线、目标与历史价格在每个时点统一转换到该日原始价格尺度；下单使用原始价格。
- 日线收盘信号只允许下一交易日触发；未触发或停牌的入场单过期，不无限等待。
- 买入数量按 100 股向下取整。初始研究范围是固定的沪深主板样本，未覆盖其他板块的不同数量要求。
- 买入当天不执行卖出。跌停封死不能卖，止损保持；停牌沿用上次估值。跳空止损按开盘附近成交，不按理想止损价。
- 日线无法恢复盘中路径；若入场日同时触及失效价与触发价，保守拒绝。无法获得队列与深度，涨停附近买单保守拒绝。
- 止损卖出先计算，但当日卖出收入不用于新入场。仍不提供精确的日内组合暴露模拟。
- 手续费最低 5 元、滑点 0.1%、印花税分日期配置均为研究假设；精确成交还需换手、流动性和券商费率模型。
- **公司行动采用合成总回报约定**：因子变化时按比例变更数量与成本，保持估值连续。这是研究近似，不是实际分红/送股结算，会产生非整数数量。正式绩效验证前需接入公司行动、现金分红、股权登记和数量处理模型。
- 固定股票池不等于历史全市场股票池；无历史 ST / 上市退市筛选，不能宣称无幸存者偏差。全市场研究需另建时点股票池。
- 数据 snapshot/hash 保存但供应商历史修订仍可能存在。研究数据与报告由使用者本地保管。
