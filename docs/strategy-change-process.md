# 策略变更流程

1. 记录变更假设：问题、参数/规则、预期改善、可能代价、哲学约束是否改变。
2. 新建 configs/experiments 配置，不覆盖基准；代码逻辑变更同步升级策略 ID。
3. 运行因果性和风控测试，重点检查确认时间、持仓归属、不可成交情况。
4. 同一数据快照比较基准与候选，同时评估组合，不能只比较单策略收益。
5. 数据按时间划分训练、验证、最终保留样本；在保留样本上的反复选择也属于调参。
6. 查看每笔交易及拒绝原因；记录未改善的假设，不删去失败实验。
7. 获得跨环境证据后才更新基准。哲学修改需单独记录，不借优化策略实施。

run manifest 保存代码指纹、数据指纹、哲学版本、样本和执行限制；配置及行情、日历、source 代码快照同时保存，可使用 source/run.py 的 csv 模式复跑。
